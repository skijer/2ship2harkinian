# OoT Asset Loader

Shared resources for OoT items, medallions and spiritual stones in MM. Extracts from a personal OoT NTSC 1.0/1.1/1.2 ROM, with z64/n64/v64 byte orders. Open Enhancements > OoT Asset Loader to extract again. The game asks before reading the chosen ROM and creating the archive; restart to mount it.

XML File OutNames isolate the extracted assets as textures/oot_*, objects/oot_*, overlays/oot_* and misc/oot_*. The exception is misc/link_animetion: OTRExporter hardcodes that folder in every player animation header, so OoT's gPlayerAnimData_* go there (no name collides with MM's). Shared 32px icons and combined jewel/medallion get-item models are included in this mod. The get-item objects of OoT's trade sequence, masks, Stone of Agony and Gerudo Card are extracted too, so other mods show those items with OoT's own icons and models instead of custom art. Sheik's harp (object_xc, for rito) and Ganon's light orb and Triforce (ovl_Boss_Ganon2, for garo and cucui-ganon) are extracted too. So are the enemy objects of the Crossworld Enemies mods (object_dh, object_bigokuta, object_yukabyun, object_bubble, object_sk2). Existing MM resources keep their names.

Mods that need an OoT resource call the service `oot_assets.require` (`bool (*)(const char* path)`) from their ModInit instead of listing it under the manifest's `requires`, which would leave them off without a word. A missing path offers the extraction once per session; the mod registers only when the service returns true. Every oot_enemy_* mod uses it.

On the first scene, oot_shared_assets.o2r is written with every shared copy that is missing, installed at the next start. It also holds Cojiro's blue cucco (objects/object_nei_cojiro), built from oot_object_niw: the white feather textures and the eye's border-connected background are tinted, and the seven limb display lists point to those copies (cojiro_assets.h).

An already extracted personal oot.o2r can be imported with mod-sdk/tools/import_oot_assets.py --source <oot.o2r> --output <mods/oot.o2r>. The import also brings OoT's song fanfares as audio/oot_sequences, audio/oot_fonts and audio/oot_samples, and each song's icon as OoT's own note in its quest colour; --songs-only adds just those to an existing archive. The ROM extraction does not include them yet: oot_items then plays its songs without a fanfare and shows its packaged note. The importer rewrites both display-list CRC references and serialized skeleton/animation paths. This installation uses the user's existing extracted OoT archive: 2,745 resources, ZIP integrity checked and references verified. OoT NTSC 1.0 extraction was verified using the normalized ROM left by the failed extraction attempt: 2,745 resources, all eight loader markers and ZIP integrity passed. NTSC 1.1/1.2 extraction remains unverified. The MM extractor now selects YAR decoding by the ROM CRC, and the host removes foreign ROM version metadata from secondary mod asset archives.
